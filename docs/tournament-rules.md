勝ち上がりや予選スコアを確定する単位**とする。釧路の試合は先後交代の2対戦だが、
旭川のBot戦は1対戦で1試合になる（K2 §0、A2 p.4）。

## 3. 釧路を主対象にした確認事項

### 3.1 勝敗と採点

K2 §1-2・§1-3では、終了の原因を区別して扱う。相手への直接Putと封鎖による勝利、
規定ターン終了時のアイテム優勢、相手の自滅・場外移動・クライアント異常などを記録する。
直接Putの勝利と自分の封鎖負けが同時に成立する場合は、直接Putを優先する。

試合結果の比較順は **相手の自滅等 → Put勝ち → アイテム数優勢**。
ただし公開細則は、各分類の数値的な重み、前後半の合算方法、アイテムを比較する範囲を
数式として定義していない。これは公開資料K2から読み取れた範囲である。

その後のU2により、このシステムでは切断やPutによる勝利を同じ特殊ポイントとして扱う。
**分類別の勝利回数を優先比較する以前の設計候補は、現在の試作では採用しない。**
各勝因の記録を残しながら、該当する勝者へ1特殊Pを付ける。
試作では「2戦の特殊P合計 → スコア合計」を採用した。この優先順位は実装者の判断であり、
公開資料の文言と同一だと主張せず、依頼者に確認してもらう項目にする。

### 3.2 再試合は採点に優先する

K2 §1-4に基づき、応答タイムアウト、サーバー側の続行不能、審判が必要とした場合などは、
単なる自滅負けとして確定させない。意図的なエラーやその他のクライアント異常については、
審判が再試合とするか、自滅として扱うかを記録する。

再試合では元の試合結果を順位・勝ち上がり計算から除外し、新マップで前後半とも再実施する。
障害が後半に発生しても、前半のスコアだけを次の試合に持ち越さない。
元データは監査用に保存し、「無効化」と「削除」を分ける。

### 3.3 進行とマップ

U1により、釧路の現行運用は **予選と本戦の2段階** とする。
通常は予選で参加者同士の総当たりを行い、本戦はトーナメントで実施する。
人数が多い場合にグループを設け、各グループ内で総当たりを行い、上位2名ずつを本戦へ送る
運用実績がある。グループ化する人数の閾値、グループ数、通常予選の通過人数は固定しない。

各試合は原則2対戦。初戦のCOOL/HOTはじゃんけんで決め、その決定結果を入力する。
2戦目は同じ参加者の先後を交換し、2対戦の結果を集計して細則の順に試合勝者を決める。
じゃんけんの勝者が先攻になるのか選択権を得るのかは今回の説明では確定しないため、
CHroSは勝者から先攻を推定せず、**確定した初戦の先後割り当て**を記録する。
大会の組み合わせ抽選と、個々の試合の先後決定は別の操作とする。

K1の「予選を実施しない」という記載とU1の現行運用は一致しない。
記載の経緯を推測せず、この設計では依頼者から確認したU1を進行の根拠として採用する。

K2 §1-1・§2では、応答制限時間の具体値は別途設定する。
マップ寸法は15×17または21×17で、配置の対称性、奇数個のアイテムと中央アイテム、
外周、開始位置の観測範囲、上下9マス目のブロック配置に条件がある。
これらは採点式とは別のマップ／運用設定に属する。

CHroS の今回の試作はマップ生成・管理やクライアント実行を行わない。
マップ識別子・版・寸法・使用条件の記録は将来設計とし、非公開マップの内容は保存・配信しない。
確認待ちなのは予選順位の決め方と同順位処理、通常予選の通過枠、本戦への配置方法、
ターン上限の実値、応答制限時間、再試合の反復上限など。

## 4. 旭川・北海道系で必要になる差分

### 4.1 Bot予選

A2 p.4では参加者がCOOL、BotがHOTの1対戦。参加者の取得アイテム数を `I`、
終了時の残りターン数を `R` とすると、勝ちは `3I + R`、負けは `3I - R`。
**時間（秒）ではなく残りターン数**を使い、負のスコアも有効とする。
Botは対戦相手として登録するが、参加選手の予選順位には含めない。

Bot戦自体の同点時処理、同スコアの予選順位、通過人数・シード配置の細部は
A1・A2だけでは確定しない。対人戦用の再試合規則を自動で当てはめない。

### 4.2 対人トーナメント

A2 p.4では2対戦の勝利数が第1基準。勝利数が並んだ場合に、各対戦の補正値を合計して比較する。
補正値は、その参加者について次のように求める。

| 対戦の結果・敗因 | 比較用アイテム値 |
| --- | --- |
| 相手のPut／相手からの封鎖による敗北 | `0` |
| 自らブロックへ移動／自分による封鎖／自分に起因する通信エラー等で敗北 | `-R` |
| 上記の敗北補正が適用されない場合 | `I` |

負けた側の生のアイテム数を上書きせず、補正値を計算結果として別に持つ。
特に自滅時は **`I - R` ではなく `0 - R`**。合計も同じなら新マップで再試合となる。
Bot予選の `3I ± R` を対人戦へ適用してはいけない。

共通規則（A2 p.1）には、Putによって勝利条件と敗北条件が同時に成立する場合の勝利優先もある。
一方、判定できない同時事象やサーバー障害は、釧路の細則を流用せず審判判断として保留する。

### 4.3 マップ・運用条件

A2 p.1–3は15×17のマップ、開始位置・ブロック配置の制約、罠を初期配置する際の事前周知、
マップレビューを定める。クライアントの選択・持ち込み等は運営設定として記録する。
v3.1.0で追加されたAI利用の申告なども採点とは別の参加手続きであり、
CHroS のスコア計算エンジンがプログラムを検査する要件にはしない。

A3のように、年度固有のルール版・罠の有無・CHaserサーバー版を組み合わせるため、
`asahikawa` という地域名だけでは規則を識別できない。

## 5. 全国交流大会の扱い

N1から予選と決勝の存在は確認できるが、今回参照した公開一次資料では、
採点式、対戦回数、同点時処理、マップ条件を確定できなかった。
北海道大会から出場することや同じCHaserを使うことは、規則が同じである根拠にならない。

全国用プロファイルは **未検証の草案** とし、開催回・開催日・主催者提供の細則・追加裁定を
入手してから有効化する。Bot予選、1／2対戦、ステージ別規則、順位・勝ち上がり設定を
差し替えられる構造を用意することを、現時点での全国対応の範囲とする。

## 6. 設計判断

以下は公開資料調査時の将来設計。U2による現在の対象範囲と、試作の自主判断は
[要件定義](./requirements.md) と [試作提案](./prototype-proposal.md) を参照する。

以下は公式規則そのものではなく、上記の差分を失わず扱うための CHroS の方針。

1. **大会・年度・ステージごとに規則を固定する。** `RuleProfile` に資料の参照版、
   対戦構成、採点規則、順位規則、マップ・再試合方針をまとめる。地域名でコードを分岐しない。
2. **事実・裁定・計算結果を分ける。** 生のアイテム数、残りターン数、終了事象、行為者と
   影響を受けた側を残し、裁定と補正値は別に保存する。`blocked` の1フラグへ潰さない。
3. **対戦数を固定しない。** `Match` は試合、`Score` はその中の1対戦の記録とし、
   対戦番号とCOOL/HOT割り当てを持つ。Bot戦に架空の後半を作らない。
4. **採点前に再試合・審判待ちを扱う。** 未入力、未開催、無効試合、引き分けを区別する。
   理由と対象範囲を記録し、無効な結果を順位や次の対戦へ流さない。
5. **順位規則と1試合の勝敗規則を分離する。** Bot予選のスコア順位、対人戦の勝ち上がり、
   総当たりの順位を別に設定する。釧路のグループ予選では組ごとに順位を計算し、上位2名を
   通過候補とする。2位境界が同順位なら、未解決のまま通過者を確定しない。
6. **表示はステージの規則から構成する。** 生アイテム、補正値、勝利数、再試合の理由を
   必要に応じて区別し、Bot戦を前半／後半として表示しない。変更時はSSEで一貫した状態を送る。

  予選の順位・同順位処理、通常予選の通過枠、本戦への配置、グループ構成、
  ターン上限・応答制限時間の実値、再試合を繰り返した場合の扱い。
- 旭川: Bot対戦が同点の場合の扱い、予選同スコアの順位決定、通過枠と組み合わせ、
  未定義の同時事象や障害の処理。規定ターン終了時のアイテム同数も勝者を推定しない。
- 全国交流大会: 対象の開催回と、採用する細則・年度固有の運用一式。

これらは調査で不足している具体的な情報であり、全機能の着手を止めるものではない。
依頼者の指示に従って自主判断を記録し、対人戦の保存・入力・集計・掲示までを試作した。
